Can a SharedWorker hold the database?

weftdb arbitrates access to one OPFS database by hand: a Web Lock election picks the tab that creates the worker, and a second SharedWorker brokers a MessagePort from every other tab straight into it. All of that exists because a synchronous access handle is exclusive and a dedicated worker belongs to one tab.

A SharedWorker is one worker per origin with a port per tab, so if it can hold that handle, the browser is already doing the arbitration and none of the machinery above has anything left to arbitrate. This page answers whether it can. The decisive row is the last but one: a value written through the first port and read back through a second means two connections shared one database.
